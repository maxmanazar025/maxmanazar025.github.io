LLM fallback zanjiri: model yiqilsa ham bot ishlasin

Bepul tarifdagi LLM API — bu 429, 503 va timeout'lar bilan yashash degani. Memora OS'da buni qanday hal qilganimni ko'rsataman.

Maxmanazar Sultonov·25 Noy 2026·6 daq o'qish

AI yordamchi foydalanuvchi uchun "ishlaydi" yoki "ishlamaydi". Unga Gemini'ning rate limit'i yoki Groq'dagi vaqtinchalik 503 qiziq emas. Shuning uchun LLM chaqiruvini tarmoq chaqiruvi kabi emas, yiqilishi kutiladigan tashqi tizim kabi loyihaladim.

1. Bitta protokol — ko'p provayder

Gemini, OpenAI, Groq va OpenRouter — hammasi OpenAI-compatible Chat Completions protokolini qo'llab-quvvatlaydi. Demak, bitta HTTP klient (httpx) va faqat base_url + API kalit almashtirilsa bo'ldi. Zanjir esa oddiy konfiguratsiya qatori:

LLM_SMART_CHAIN=gemini/flash,gemini/flash-lite,groq/llama
LLM_FAST_CHAIN=gemini/flash-lite,groq/llama

Kaliti berilmagan provayder zanjirdan avtomatik tushib qoladi — kod o'zgarmaydi.

2. Ikki turdagi xato

Hamma xato bir xil emas. Men ularni ikkiga ajrataman:

  • Vaqtinchalik — 408, 429, 500, 502, 503, 504, timeout, ulanish xatosi. Bir oz kutib, xuddi shu route'ni qayta urinish kerak.
  • Qayta urinib bo'lmaydigan — 400, 401, 404 (noto'g'ri model nomi, yaroqsiz kalit). Qayta urinish — vaqtni yo'qotish. Darhol keyingi route'ga o'tamiz.

3. Exponential backoff + jitter

Qayta urinishlar orasidagi kutish har safar ikki baravar oshadi, ustiga tasodifiy "jitter" qo'shiladi — shunda bir nechta so'rov bir vaqtda qayta urilib, serverni yana bo'g'ib qo'ymaydi. Agar server Retry-After sarlavhasida qisqa vaqt bersa — shunga amal qilamiz.

async def call_chain(routes, messages):
    for route in routes:
        if route.cooling_down(): continue      # yaqinda yiqilgan — o'tkazib yuboramiz
        for attempt in range(MAX_RETRIES):
            try:
                return await route.complete(messages)
            except RetryableError as e:
                delay = e.retry_after or BASE * 2 ** attempt
                await asyncio.sleep(delay + random.uniform(0, delay / 2))
            except FatalError:
                break                               # keyingi route'ga
        route.start_cooldown()
    raise LLMError("Barcha route'lar yiqildi")

Yuqoridagi kod g'oyani ko'rsatish uchun soddalashtirilgan.

4. Cool-down: bir marta yiqilgan route'ga qaytib urilmaslik

Agar route barcha urinishlarni tugatsa, u qisqa muddatga "sovutiladi". Keyingi so'rovlar uni umuman chaqirmay, to'g'ridan-to'g'ri sog'lom route'ga boradi. Aks holda har bir xabar yiqilgan modelda retry kutib, foydalanuvchi uchun bot "sekin" bo'lib qoladi.

5. Provayder almashganda tarix buzilmasligi

Nozik muammo: suhbat tarixida bitta provayder yaratgan assistant xabarlari bor, keyingi qadam esa boshqa provayderga ketishi mumkin. Ba'zi provayderlar o'zlarining maxsus maydonlarini qaytarib olishni talab qiladi, boshqalari esa ularni tushunmaydi. Yechim — har bir xabarni qaysi provayder yaratganini belgilab qo'yish va boshqa provayderga yuborishda uni ko'chma OpenAI formatiga (role, content, tool_calls) qisqartirish.

6. JSON'ni "yumshoq" parse qilish

Modelga "faqat JSON qaytar" desangiz ham, u ba'zan ```json ichiga o'raydi yoki oldidan bir gap qo'shadi. Shuning uchun parser avval fence'larni olib tashlaydi, keyin birinchi { / [ va oxirgi } / ] orasini kesib oladi.

Natija

  • Bitta provayder yiqilsa — foydalanuvchi buni sezmaydi.
  • Barcha route'lar yiqilsa — worker egasiga qisqa diagnostika xabari yuboradi (rate-limit bilan, spam bo'lmasligi uchun).
  • Yangi model chiqsa — faqat .env o'zgaradi.

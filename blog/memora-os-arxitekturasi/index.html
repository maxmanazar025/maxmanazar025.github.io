Arxitektura

Memora OS: bot, worker va bitta PostgreSQL

Bitta talaba uchun proaktiv AI yordamchini qanday qurdim — va nega eng muhim qarorlarim "nima qo'shmaslik" haqida bo'ldi.

Maxmanazar Sultonov·25 Noy 2026·7 daq o'qish

Memora OS — Telegram'dagi shaxsiy akademik yordamchim. U dars jadvalimni universitetning Google Sheets'idan o'qiydi, darsdan 15 daqiqa oldin ogohlantiradi, dars tugagach "bugun nima o'tildi?" deb so'raydi va javobimdan uy vazifasini ajratib, Google Tasks'ga yozadi. Ertalab xulosa, yakshanba kuni haftalik hisobot yuboradi.

Eng qiziq tomoni — bu funksiyalar emas, balki ularni ishonchli ishlatadigan arxitektura. Quyida asosiy qarorlarni ko'rib chiqaman.

1. Ikki jarayon: biri reaksiya, biri vaqt

Tizimda ikkita asosiy konteyner bor va ular bir xil Docker image'dan ishga tushadi:

  • bot — faqat Telegram update'lariga javob beradi: menyu tugmalari, callback'lar, erkin matn va ovozli xabarlar.
  • worker — faqat vaqtga qarab harakat qiladi: ertalabki brifing, T-15 ogohlantirish, dars yakunidagi so'rov, eslatmalar, sinxronlash.

Ular bir-biriga to'g'ridan-to'g'ri murojaat qilmaydi. Yagona aloqa vositasi — PostgreSQL qatorlari. Masalan, worker dars tugaganda conversation_state = awaiting_lesson_log deb yozib qo'yadi, bot esa keyingi xabarimda shu holatni o'qiydi. Natijada biri qayta ishga tushsa, ikkinchisi bundan bexabar ishlayveradi.

# docker-compose.yml (qisqartirilgan)
services:
  db:       # postgres:16-alpine + healthcheck
  migrate:  # Alembic migratsiyalari, keyin chiqib ketadi
    depends_on: { db: { condition: service_healthy } }
  bot:      # Telegram long polling
    depends_on: { migrate: { condition: service_completed_successfully } }
  worker:   # proaktiv dvigatel
    depends_on: { migrate: { condition: service_completed_successfully } }

migrate — bir martalik servis: sxemani yangilaydi va chiqadi. bot va worker faqat u muvaffaqiyatli tugagandan keyin ishga tushadi. Bu "kod yangi, sxema eski" degan klassik xatoni yo'q qiladi.

2. Nega Redis yo'q?

Odatiy refleks: "navbat kerakmi? Redis qo'yamiz". Lekin bu tizimda bitta foydalanuvchi bor. Redis qo'shish — ikkinchi holatli servis va ikkinchi "haqiqat manbai" degani, throughput bo'yicha esa hech qanday foyda yo'q.

Buning o'rniga hamma narsa Postgres'da:

  • Bildirishnomalar ledger'i — har bir yuborilgan xabar uchun UNIQUE dedupe kaliti. Worker qayta ishga tushsa ham, bir xil ogohlantirish ikki marta ketmaydi.
  • Outbox flag — Google Tasks'ga yuborilishi kerak bo'lgan vazifalar shu yerda navbatda turadi.
  • Advisory lock — bir vaqtda faqat bitta worker "leader" bo'ladi.
Tranzaksiya va uniqueness constraint'lar keshga qaraganda kuchliroq kafolat beradi. Agar tizim multi-tenant bo'lsa — ledger va outbox jadvallari broker qo'yish uchun tayyor "tikuv" joylari.

3. Cron emas — stateless tick loop

Worker har 20 soniyada, soatga tekislangan holda "tick" qiladi. Har tick'da u bazadan "hozir nima qilish kerak?" degan savolga javob hisoblaydi: brifing vaqti keldimi, 15 daqiqadan keyin dars bormi, dars tugadimi. Xotirada saqlanadigan job store yo'q — demak, restart'da hech narsa yo'qolmaydi va cron drift ham bo'lmaydi.

4. So'rov marshruti: tez yo'l va agentlar

Har bir xabar LLM'ga borishi shart emas. Reply-klaviatura tugmasi bosilsa — bu fast path: ekran to'g'ridan-to'g'ri Postgres'dan chiziladi, LLM chaqirilmaydi. Erkin matn kelsa, avval suhbat holati tekshiriladi, keyin tezkor model JSON ko'rinishida niyatni aniqlaydi va ixtisoslashgan agentlardan biriga yo'naltiradi: jadval va kalendar, vazifalar, o'qish murabbiyi yoki umumiy agent. Har bir agentning o'z tool'lari bor.

Muhim detal: agent kalendarga hodisa qo'shishdan oldin tasdiqlash kartasini ko'rsatadi (human-in-the-loop). AI taklif qiladi — qarorni men qabul qilaman.

5. Xavfsizlik: faqat egasi

Bot shaxsiy, shuning uchun eng birinchi middleware — OwnerOnly: boshqa chat ID'lardan kelgan update'lar jimgina tashlanadi. Hech qanday javob, hech qanday xato xabari — hujumchiga signal ham yo'q.

Xulosa

  • Jarayonlarni vazifasiga qarab ajrating: reaksiya va vaqt.
  • Ular o'rtasidagi aloqani baza orqali qiling — shunda har biri mustaqil yiqilib, mustaqil turadi.
  • Yangi servis qo'shishdan oldin so'rang: mavjud baza buni kafolatlay oladimi?
